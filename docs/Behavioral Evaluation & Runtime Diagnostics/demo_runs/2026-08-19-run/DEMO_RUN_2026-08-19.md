## 3. The hollow-Growth proof (run against the real artifacts)

```text
score_answer_structured("What did I get wrong or oversimplify about medieval cooking?",
                        <g_24136ed3db/claims.json — mathematics>)
→ True  "field is a set F together with two binary operations on F"
score_answer_structured("Why do octopuses dream?", <same>) → False
_subject_terms("What did I get wrong or oversimplify about evolutionary biology?")
→ ['did','get','wrong','oversimplify','evolutionary','biology']
```

On the 12 real `claims.json` files the first match is a topic word (or `now` ⊂
"known" for g_dd89). The answer excerpt is always a **definition sentence** from
the fetched page, e.g. "Mathematics is a field of knowledge…". That cannot answer
"what did I get wrong," so the scorer measures *"I fetched a page about X."*
Pages are fetched by topic, so the check is a tautology.

The same terms feed `_find_prior_claims` (`goals/handlers/research.py:121-141`).
Every claims file shares `did/get/wrong/oversimplify`, so the newest one always
matches:

| Citing goal | "Builds on" |
|---|---|
| nature of mathematics | foundations of quantum mechanics |
| mathematics | The Daily Stoic |
| evolutionary biology | mathematics |
| history | consciousness |
| emergence in complex systems | stoic philosophy |
| quantum mechanics foundations | evolutionary biology |
| foundations of quantum mechanics | emergence |
| biology / evolutionary biology | history |
| The Daily Stoic | history |
| stoic philosophy | quantum mechanics foundations |

The prior claims are then **inserted into the new goal's sources**. So every memo
is contaminated with an unrelated topic's relations, and that is how the promoted
quantum exemplar came to cite "my prior claims [g_40fe7f09e0]" (evolutionary
biology).

Separate ledger caveat: reuse rows stamp `goal_id` = the artifact's **owner**
(`effect_ledger.py:823`), not the citing goal. A run analysis cannot see who
reused what without the memo footers. Add `citing_goal_id` to the row.

   `did/get/wrong/oversimplify/now/know/find/makes/…` (the question-template

   `_claim_subject_terms`, and use word-boundary matching, not `in`.

   I get wrong." For revision-shaped questions, require a claim that **differs from
